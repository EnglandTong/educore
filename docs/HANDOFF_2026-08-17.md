## 6. 已知风险与代码定位

以下是下一个 AI 优先核查的方向；不能仅凭这些条目直接修改代码，因为当前 M82 是 audit-only。

1. **治理冲突**：`docs/TARGET.md` 是 M82，`STATUS/PENDING/NEXT_ACTIONS/CMS/Work_Order_Active` 仍是 M81A。先解决状态权威，再继续。
2. **权限模型分裂**：
   - `packages/types/src/permissions.ts`：`PERMISSION_MATRIX` 包含多种 volunteer/school 等角色。
   - `apps/api/src/middleware/auth.ts`：JWT 类型也包含更宽角色集合。
   - `apps/api/src/modules/auth/auth.schema.ts` 和 `apps/api/src/services/auth.service.ts` 的注册角色主要是 `student | parent | teacher`。
   - `apps/api/src/models/User.ts` 的 Mongo enum 又包含更多角色。
   必须建立“角色允许进入系统、角色如何获得、权限如何执行”的单一权威，并用 allow/deny 矩阵验证。
3. **School 数据完整性**：`apps/api/src/modules/school/school.routes.ts` 约第 68、92、111 行附近涉及教师加入/移除和 classes placeholder；必须确认 teacherIds、角色降级、school scope、IDOR 和错误语义。
4. **Pseudo-success placeholder**：`apps/api/src/modules/sync/sync.service.ts` 的 `getSyncStatus()` 固定返回空状态；school classes 也明确标为 placeholder。不能把 HTTP 200 当成完成。
5. **E2E/mock 边界**：`apps/web/e2e/e2e-mocks.ts` 和 `apps/web/e2e/mocks/*` 会返回 200 envelope。mock E2E 可证明 UI wiring，不可证明 API、数据库、权限、同步或真实部署 topology。
6. **Web 测试/质量门禁薄弱**：web 单测无测试文件仍以 0 成功；lint 是 echo。必须在审计中明确“自动检查通过但覆盖为空”。
7. **缓存证据**：当前 Turbo 多项 `cache hit`。M82 要记录缓存状态；若要证明源代码当前状态，应在授权范围内安排 uncached/clean-install 验证，不要偷偷扩大范围或改依赖。
8. **PWA/offline 复杂度**：web build 生成 service worker 和 precache；任何后续账号切换、logout、offline queue 工作都必须证明 cache eviction、account binding、retry idempotency。
9. **学生隐私**：teacher、parent、school、QA、volunteer endpoint 都要做跨账号、跨 school、跨 role deny；前端路由 guard 不是后端授权证据。
10. **历史状态不可直接复用**：M49/M50-M80/M81A 的 PASS 是时间点证据；Fresh evidence overrides historical PASS。
