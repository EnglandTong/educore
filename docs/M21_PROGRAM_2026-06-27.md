# M21 Program - M20 Handoff Recovery

Owner: MRT-Controller-QA
Status: Dispatched

## Milestone Goal

Recover the failed M20 review by producing the missing consolidated M20 Developer handoff and synchronizing the recovery state for Controller/QA review.

## Program Scope

- Bounded docs-only recovery of the missing M20 consolidated handoff.
- Evidence traceability across M20 program, dispatch, work orders, QA failure record, and loop logs.
- State publication for review handoff.

## Non-Goals

- Product code changes.
- UI/UX changes.
- New architecture, new subsystem, new shared layer, or production deployment work.
- Changes to `docs/ACCEPTANCE.md`, `docs/STOP_RULES.md`, or TARGET core goals/non-goals.
- Deleting, rewriting, or weakening historical evidence.

## Work Order Execution Order

1. `P21-01` - Reconstruct M20 consolidated handoff. Complexity: `Standard`.
2. `P21-02` - Publish M21 recovery state and review handoff. Complexity: `Standard`.

## Dependencies

- `P21-02` depends on successful completion and verification of `P21-01`.
- Developer may proceed from `P21-01` to `P21-02` only if no stop rule is triggered and the required handoff file exists.

## Auto-Advance Rules

Developer may automatically continue to the next listed work order when:

- the previous work order is complete;
- verification commands pass;
- handoff evidence is written;
- changes remain inside allowed files;
- no `docs/STOP_RULES.md` condition is triggered;
- no verification command fails three consecutive times for the same unresolved reason.

Developer must stop and return to Controller/QA or Owner when:

- a stop rule is triggered;
- the recovery requires changing product code or project architecture;
- evidence conflicts with the M20 failure record;
- the required handoff cannot be reconstructed from existing project evidence;
- external credentials, production data, network provisioning, or out-of-repo writes are required.

## Final Program Handoff Requirement

At program end, Developer must leave:

- `docs/HANDOFF_M20_PROGRAM_DEVELOPER.md`
- per-work-order handoff notes in `docs/LOOP_RUNS.jsonl`
- status updates in `docs/STATUS.md`, `docs/NEXT_ACTIONS.md`, `docs/PENDING.md`, and `docs/CURRENT_ROLE_INSTRUCTIONS.md`

Final Developer state must be `Ready for Controller/QA Review` or `Blocked`. Developer must not mark M20 or M21 as `Accepted` or `Completed`.
