## 1. Program Goal

Harden the accepted M27 Teacher Assignment Overview Dashboard by proving the frontend build compiles, aligning mastery-level display with existing UI patterns, and making the page discoverable from teacher navigation.

## 2. Program Scope

- Verify `@educore/web` typecheck and production build.
- Fix only blocking TypeScript errors in M27-created or M28-touched frontend files.
- Replace inline CSS-variable mastery badges with the shared `Badge` component.
- Add a teacher sidebar link to `/teacher/assignments`.
- Produce consolidated Program handoff and update governance state.

## 3. Non-Goals

- No backend changes, new API endpoints, or database schema modifications.
- No dedicated assignment-management API.
- No assignment create/edit/delete functionality.
- No new architecture, shared layers, or subsystems.
- No modifications to `packages/algorithms/`, `modules/`, or `apps/api/src/`.
- No production deployment.
- No dependency installation if local packages are unavailable.

| Order | ID | Complexity | Task | Predecessor |
|---|---|---|---|---|
| 1 | P28-01 | Standard | Verify `apps/web` typecheck and build; fix blocking M27-scope TS errors only | none |

## 5. Dependency Rules

- P28-01 must be verified and handed off before P28-02 begins.
- P28-02 must be verified and handed off before P28-03 begins.
- P28-03 must be verified and handed off before P28-04 begins.

Developer may auto-advance to the next Work Order provided:

- The previous Work Order has a handoff with evidence.
- No stop rule is triggered.
- No verification command failed without a documented fix.
- No scope conflict is detected.
- Fewer than three consecutive failures of the same verification command occurred.

Developer must stop and return to Controller/QA if:

- Build/typecheck failures require changes outside Allowed Files.
- Dependency installation or external network access is required.
- Any STOP_RULES item is triggered.
- Three consecutive failures of the same verification command occur for the same unresolved reason.

## 6. Complexity Definitions

- **Lite**: Single-file change, navigation link, or handoff-only work. Low risk.
- **Standard**: Build verification with possible targeted fixes and evidence capture.
- **Deep**: Not used in this Program.
