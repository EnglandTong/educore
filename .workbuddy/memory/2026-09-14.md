## 完整审查结论（2026-09-14，只读审计）

### 总体判断
质量风险不在功能缺失，而在「证据链与真实运行之间的缝隙」。架构方向正确（离线优先、优雅降级、BKT 权威、幂等 eventId），短板集中在最后一公里，且全部落在 M89/M90/M91 射程内——路线图不需要改方向，只需把以下项写进对应工单验收标准。

### P0
- refresh token 长期明文存 localStorage。证据：`authStore.ts` 用 zustand persist（默认 localStorage）存 accessToken + refreshToken，refresh 有效期 7 天。影响：① XSS 可窃取长效凭证；② 与 M89「共享设备隐私」目标直接冲突——7 天有效 refresh token = 换账号不登出就换人。建议作为 M89 第一优先项（httpOnly cookie 或 sessionStorage + 缩短有效期）。

### P1
- 离线队列 4xx 毒丸重试。证据：`sync-queue.ts:79-83` 任何错误都 incrementRetry 重试到 5 次；400 校验错误（永久失败）浪费带宽重试，409 幂等冲突本该算成功却计为 failed。建议：区分 4xx（立即出队/标记死信）与 5xx/网络错误（重试），409 归入 synced。
- 双离线存储漂移。证据：`TrainingPage.tsx` 同时写 sessions-store（addOfflineAnswer）与 sync-queue（enqueueOperation）两条路，无对账机制；重放成功后 sessions-store 的 synced 标记与队列删除是两个事务，崩溃窗口内漂移。这是 M91「非 mock 断网重放」最该打的靶子。
- Web 端零单测。证据：测试只有 API 侧（unit/integration/security）+ 4 个 Playwright e2e；web 无任何 *.test.ts。PROJECT_BOARD 已承认「lint 曾为 echo、0-test 可假绿」——M88「真绿灯」必须包含前端单测，至少覆盖 sync-queue 与 auth client。

### P2
- 测试 mock-by-path 脆性：`learning.service.test.ts` 用 vi.mock 相对路径 mock 全部 model 层，model 重构时测试静默失真。M90 硬化 DTO 时建议转真 DB（mongodb-memory-server）做核心链路测试。
- Docker 拓扑两处隐患：`docker-compose.yml` Mongo/Redis 端口映射到宿主机（生产暴露面）；web 构建期烘焙 VITE_API_URL，运行时改 API 地址需重建镜像。建议：生产 profile 收端口；前端 nginx 反代 /api 走容器网络。
- 文档债：docs/ 343 个 md，80+ 为 M14–M49 的 DISPATCH/HANDOFF 历史包裹。不删（Non-Goal 禁止破坏性清理），建议后续把「归档压缩」列为低优先任务。

### P3
